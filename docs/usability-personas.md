# Parichay usability evaluation — 14 September 2026

## Method and evidence

This is an expert, simulated persona evaluation using the running Flask application in Chrome, **not research with recruited people**. Six independent fresh browser contexts completed the full scenario using visible controls and accessible labels: professional (English, 390×844 and 1440×900), parent (Hindi, 360×800 and 768×1024), and lower-confidence mobile user (Hindi, 320×568 and 412×915). Each created two qualifications, career and family details, introduction and interests, cropped a real dummy photo, opened/zoomed/closed preview, changed the work city, downloaded a real PDF, exercised sharing and recovered the draft after reload. The parent added optional community, birth date/time, birthplace, rashi and nakshatra. Other personas skipped culture. Filled-entry removal was cancelled successfully.

Observed interaction logs, screenshots and six PDFs are in `tmp/qa/usability/before/`; repeatable scripts are `scripts/persona_usability_check.py` and `scripts/usability_edge_check.py`. Locator corrections during automation are not counted as product failures. Automation elapsed seconds do not measure human task time. Sharing was intercepted at the operating-system boundary: the actual File payload was inspected, and the unsupported-browser fallback was exercised. No message was sent and WhatsApp receipt is unverified.

Additional interactive probes covered all nine requested portrait sizes, 844×390 landscape, browser Back, five immediate refreshes, actual Chromium page scaling, 200% root text size, invalid/small photo selection, input Enter behavior, and a separate cold 320px session with 300ms latency, 400kbps download/200kbps upload and 4× CPU throttling. Keyboard focus and viewport behavior are emulations; a physical Android keyboard, camera picker and TalkBack require device testing. No horizontal overflow occurred in the six standard journeys. A 320px overflow was observed with 200% text still active during the photo-error probe; diagnosis identified the header controls, not the error text, as the overflowing element.

### Why the major failures happen

- **U01:** latest text disappears → save has not started → a debounce delays durable storage → persistence and rendering share an optimization boundary. Separate durable writes from delayed visual work.
- **U02:** Back seems ineffective → popup remains over a changed form → modal has no navigation state → view history models form steps only. Model the visible popup in the same history.
- **U03:** Download becomes unreachable → nav grows below the viewport → fixed non-scrolling panels retain desktop mode → layout adaptation only measures viewport pixels. Include text enlargement in the mode decision.
- **U04:** zoom removes actions → keyboard CSS is applied → viewport shrink is assumed to mean keyboard → focus and zoom scale are ignored. Detect the actual conditions together.
- **U05:** generated file does not produce a clear share path → success stays offscreen and fallback repeats download → implementation ends at Blob creation → no explicit hand-off state. Make ready-to-share a visible, named state.
- **U06:** invalid file seems ignored → error appears below content → generic error component has no focus/scroll behavior → failure paths were not designed around the initiating action. Give photo failure the same deliberate recovery behavior as export failure.

P0 U01 first. P1 U02–U06 next. Then P2 U07–U16. P3 U17 is documented, with no attachment-system expansion.

### Final persona outcomes

- **Professional:** both 390px and desktop flows complete with a modern design, optional culture skipped, two qualifications, interests, photo, corrected work city and PDF. No data re-entry is needed after template changes or returning to the draft. Under-ten-minute human completion is not established by automation.
- **Parent:** both Hindi mobile/tablet flows complete for a daughter, with family, community and birth details, a traditional Ganesha design, named PDF and clear sharing fallback. Whether a parent can finish without help requires real participant testing.
- **Lower-confidence mobile user:** both 320px/412px Hindi flows complete, including photo and edit-back tasks. Clearer next-field behavior, reversible photo replacement and visible recovery reduce inferred uncertainty. Low-end hardware performance remains unmeasured outside CPU/network emulation.

### Device conclusions

- **320–360px:** persistent named navigation and Preview/Continue; fitted A4 can be enlarged in the popup. Enlarged text no longer pushes header actions outside the viewport. Photo errors and download completion receive focus and scroll into view.
- **390–412px:** complete mobile flow passes in both languages; browser Back behaves as a popup dismissal. Input focus plus visual-viewport conditions control keyboard accommodation.
- **768–1024px tablet:** the compact editor and preview popup remain intentional; all sections can be selected directly without a crowded three-panel layout.
- **1280–1920px desktop:** header, navigation and preview remain stationary while the form scrolls. Enlarged text switches to the compact presentation rather than clipping the fixed sidebar.

### Regression evidence

- Six final independent persona journeys; six real PDFs; no browser JavaScript errors (`tmp/qa/usability/after/journeys.json`).
- Focused Back/reload/zoom/photo/throttling evidence (`edges.json`) and extended photo/tab-close/privacy/220 enlarged-text checks (`recovery.json`).
- 308 standard English/Hindi editor checks over fourteen viewport pairs; normal desktop geometry, validation, entries, recovery and PDF passed (`scripts/ux_redesign_check.py`).
- All nineteen templates switched with a photo and hidden family data; six sizes, Hindi reload and PDF passed (`scripts/check_figma_browser.py`).
- 24 landing checks, product UI contrast scan with zero failures, keyboard focus, reduced motion, offline/storage exhaustion and export retry passed (`scripts/paper_plum_check.py`). Document artwork is excluded from this UI contrast scan; this is not a full WCAG certification.
- 59 automated tests passed, including actual PDFs for all nineteen themes, image archives, long Hindi pagination, schema validation, hidden fields, CSRF and secure image handling.

### Remaining research and platform risks

Recruit several people matching each archetype and observe unaided task completion, actual hesitation and errors; the inferred thoughts above must not be presented as interview findings. Test budget Android Chrome with its real keyboard, camera/gallery permissions, Downloads application and WhatsApp, plus iOS Safari and TalkBack/VoiceOver. Obtain native Hindi copy feedback, including birth-date/time and financial/privacy terms. Confirm PDF appearance on physical printers and real shared phones. Measure cold loading on representative hardware and production hosting; a single throttled comparison cannot establish a performance distribution. Browser clearing/eviction and simultaneous editing tabs can still affect local drafts. No WhatsApp delivery, ten-minute human completion, or independent accessibility certification is asserted.
